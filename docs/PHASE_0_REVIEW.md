# Phase 0 — самопроверка (ревью документов)

Дата: 2026-11-08. Кода ещё нет, поэтому «баги» здесь — ошибки и противоречия в проекте. Исправлены в этом же коммите.

## Ошибки проекта, которые стали бы багами в коде

| # | Проблема | Что было бы | Исправление |
|---|---|---|---|
| 1 | Debounce склеивал все сообщения чата | в группе реплики разных людей сливались в одно сообщение | ключ debounce — (chat_id, user_id) |
| 2 | Не было фильтра собственных сообщений | userbot получает и свои исходящие — Аля отвечала бы сама себе в цикле | фильтр is_outgoing; ручные сообщения владельца с аккаунта считаются репликами Али |
| 3 | Не было политики для незнакомцев в личке | на userbot пишет кто угодно: спам и счёт за API | политика незнакомцев, лимиты (T19) |
| 4 | Чужие сообщения группы шли в общую историю без пометки | факты извлекались бы из разговоров, где Аля не участвовала, вопреки решению «1–3 дня» | поля context_only / addressed_to_alya, TTL, запрет извлечения фактов |
| 5 | Эмоции только по (пользователь, чат) | «скуку» для проактивности негде взять | глобальное настроение в ADR-0005 |
| 6 | Нет таблиц для журнала удалений и инициатив | ADR-0009 и ADR-0011 нельзя было бы реализовать | deletion_journal, proactive_events |
| 7 | Поиск по векторам без фильтра model_id | после смены модели эмбеддингов сравнивались бы несовместимые векторы | фильтр по model_id + переиндексация |
| 8 | Разметка «Telegram HTML» для TDLib | TDLib работает с formattedText/entities | разметка по транспорту |
| 9 | Правки и удаления сообщений не обрабатывались | удалённое в Telegram оставалось бы в памяти | обработка правок и удалений |
| 10 | Инициатива в группах без ограничения стоимости | вызов модели на каждое сообщение каждой группы | сначала бесплатный фильтр, модель — только для прошедших |
| 11 | Bot API назван «резервом» | это другой аккаунт, при блокировке @AlysiaNya не спасёт | честная формулировка в ADR-0002 |

## Устаревшие места и противоречия

- PHASE_0_REPORT: «Userbot → Bot API», «провайдер эмбеддингов не выбран», «граница дня — вопрос», «проактивность выключена» — противоречили решениям владельца.
- SECURITY T8: «проактивность по умолчанию выключена» — противоречило ADR-0009.
- ARCHITECTURE §9: «что делать с бэкапами — вопрос» — решено в ADR-0011.
- Файл ADR-0002 назывался telegram-bot-api-primary — переименован в telegram-userbot-primary.
- Опечатка «деклярирует».
- .gitignore не закрывал файлы сессии TDLib (td_database/, *.binlog) и варианты .env.

## Что остаётся непроверенным

- Лицензии Pytdbot, tdjson, TDLib; наличие wheel tdjson под архитектуру сервера.
- Точные имена методов TDLib (реакции, стикеры) — сверить в Phase 4.
- Поддержка tool calling и аудио у конкретных моделей OpenRouter — проверяется при старте.
- Пороги Addressee Detector и проактивности — стартовые, нужна калибровка на реальных чатах.
