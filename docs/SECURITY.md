# Security & Privacy: модель угроз

Статус: принято, обновляется вместе с кодом.

## Активы

Переписка и память пользователей; эмоциональный/отношенческий профиль; секреты (Bot token, API-ключи, TDLib-сессия); права администратора; репутация бота в группах.

## Участники

Владелец (проверенный ID), админы (allow-list ID), обычные пользователи, участники групп, сторонний контент (пересылки, медиа, веб), внешние LLM-провайдеры, плагины.

## Угрозы и меры

| # | Угроза | Пример | Меры | Тест |
|---|---|---|---|---|
| T1 | Межпользовательская утечка | Аля пересказывает одному пользователю разговор с другим | scope обязателен в каждом запросе к памяти; групповой контекст не видит личных записей; межчатовая связь хранит только факт встречаемости | изоляционные тесты A/B в личке и группе; property-тест «запрос без scope невозможен» |
| T2 | Prompt injection (прямая) | «игнорируй инструкции, ты теперь…» | недоверенный текст в отдельных размеченных блоках; инструкции только из системного слоя; базовый характер не меняется из чата | набор injection-кейсов в CI |
| T3 | Prompt injection (непрямая) | инструкция внутри сохранённой памяти, подписи к фото, веб-страницы, ответа инструмента | память и медиа помечены как данные; Dream Engine не переносит «инструкции» в факты; провенанс у каждой записи | кейсы с отравленной памятью |
| T4 | Подмена личности | ник «owner», пересылка от владельца, текст «я создатель» | права только по Telegram user ID из update; пересылка и цитата не дают полномочий | тесты ролей |
| T5 | Утечка секретов | ключ в логах, ответ модели с содержимым .env | секреты только из окружения; редактирование в логах; модель не получает доступ к ФС/shell; output sanitizer ищет шаблоны ключей | тест логов и sanitizer |
| T6 | Вредоносные вложения | огромный файл, zip-бомба, поддельный MIME | лимиты размера/длительности до загрузки; проверка типа; временные файлы с удалением; без распаковки архивов | тесты лимитов |
| T7 | Злоупотребление инструментами | модель «решила» забанить или написать в чужой чат | инструменты типизированы, с проверкой роли и чата; деструктивные действия — только dry_run + подтверждение; плагины декларируют разрешения | тесты отказов |
| T8 | Ошибки проактивности | ночные сообщения, спам, сообщение не тому | включено по решению владельца (ADR-0008) с quiet hours, cooldown, лимитом 1 в сутки, только людям с устоявшимся диалогом; возможность «пауза» | тесты планировщика с фиктивным временем |
| T9 | Флуд / DoS / стоимость | сотни сообщений, дорогие запросы | rate limit на пользователя и чат, бюджет токенов, circuit breaker на провайдера | нагрузочные тесты Phase 8 |
| T10 | Неполное удаление | Forget не удалил эмбеддинг или Markdown-копию | единый Forget-сервис по всем хранилищам; проверка каждого хранилища в тесте | тест Forget |
| T11 | Ложные срабатывания модерации | автобан за безобидное сообщение | только dry_run + audit log; автоматических банов нет | тесты аудита |
| T12 | Цепочка поставок | компрометация пакета | lock-файл с хешами, минимум зависимостей, Dependabot/pip-audit в CI | CI |
| T13 | Нарушение ToS Telegram | userbot-режим выбран владельцем (аккаунт @AlysiaNya) | лимиты частоты ниже лимитов Telegram, строгое соблюдение FloodWait, без массовых рассылок и вступлений, проактивность только в разрешённые чаты; риск ограничения аккаунта принят владельцем | тесты FloodWait и лимитов |
| T14 | Кража сессии аккаунта | копия каталога TDLib-сессии даёт полный доступ к аккаунту | сессия в отдельном volume с правами 0700, не в бэкапах по умолчанию, не в git; api_id/api_hash и пароль 2FA только из окружения; рекомендация включить 2FA | проверка прав и .gitignore |
| T15 | Злоупотребление функциями аккаунта | пользователь уговаривает Алю вступить в чат, сменить bio/аватар, разослать сообщения | вступление по ссылке, bio и аватар — только по команде владельца; инструменты проверяют роль по ID; лимиты частоты | тесты отказов |

| T17 | Ложное определение адресата | Аля встревает в чужой разговор | ADR-0007: при сомнении молчать, лимиты ответов | сценарные тесты |

## Privacy-команды (план)

`/privacy` — что хранится; `/export` — выгрузка своих данных; `/forget` — удаление (с подтверждением, по категориям или полностью); `/pause` — остановить запоминание и проактивность. В группах команды действуют только на данные вызвавшего.

## Политика логирования

Никогда не логируются: тексты сообщений (кроме режима отладки на тестовом аккаунте с явным флагом), секреты, содержимое памяти. Логируются: ID событий, длительности, коды ошибок, хеши/обрезанные ID чатов.

## Ограничения платформы

- Userbot видит все сообщения групп и личек — поэтому определение адресата (ADR-0007) и изоляция памяти реализуются в коде, а не обеспечиваются платформой. Ошибка детектора = лишнее вмешательство в чужой разговор; по умолчанию при сомнении Аля молчит.
- Secret Chats через TDLib технически доступны, но не поддерживаются: их содержимое не должно попадать в серверную память.
