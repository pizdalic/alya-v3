# План реализации

Статус: предложение (Phase 0). Оценки сложности — экспертные, не измеренные.

Общие правила для каждой фазы (Definition of Done из SPEC_V3): функции реализованы, а не имитируются; тесты добавлены **и реально запущены**, результат указан в отчёте; нет известных критических ошибок; конфигурация и миграции обновлены; документация соответствует коду; секреты и PII не попадают в логи; отчёт пользователю. Переход к следующей фазе — только после подтверждения.

## Порядок внутри Phase 1 (после подтверждения)

1. Повторная проверка версий всех зависимостей, помеченных в DEPENDENCIES.md как «не проверено».
2. Проверка среды выполнения тестов (см. риск R-9 в PHASE_0_REPORT).
3. Каркас и конфигурация → DI/Event Bus → хранилище и миграции → lifecycle/health → Docker → CI.
4. Отчёт Phase 1 с командами и реальными результатами тестов.

## Критерии готовности ключевых фаз (кратко)

- **Phase 1:** `alya --check-config` и healthcheck работают; миграции применяются на пустую БД идемпотентно; CI зелёный.
- **Phase 2:** тест «пользователь A не видит память пользователя B» в личке и группе; Forget удаляет запись из всех хранилищ (проверка по каждому); поиск работает без эмбеддингов; NumPy и sqlite-vec дают совместимые top-k.
- **Phase 4:** быстрые сообщения склеиваются; RetryAfter соблюдается; в группе без упоминания нет ответа; перезапуск не теряет outbox.
- **Phase 5:** прерывание консолидации на середине не портит данные.
