# ADR-0010: /forget и резервные копии

- Статус: **принято** (2026-11-08, решение архитектора по поручению владельца)

## Решение
- /forget удаляет данные из рабочей БД, FTS, эмбеддингов, связей, сводок и Markdown-зеркала **сразу**, в одной операции.
- Каждое удаление пишется в журнал удалений (tombstones): ID записи/пользователя/чата и время, **без содержимого**.
- Бэкапы хранятся ограниченное время (по умолчанию 7 дней) и удаляются по сроку; бэкапы не пересобираются.
- При restore журнал удалений автоматически применяется повторно, поэтому удалённое не «воскресает».
- /privacy сообщает пользователю срок, за который данные исчезнут из бэкапов.

## Альтернативы
Пересобирать все бэкапы при каждом /forget — дорого и рискованно для целостности.

## Последствия
Тест: backup → forget → restore → данные отсутствуют.
