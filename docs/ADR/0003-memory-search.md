# ADR-0003: SQLite FTS5 + эмбеддинги в BLOB + NumPy cosine + RRF

- Статус: предложено (Phase 0, 2026-11-08)

## Контекст
alya-v2 использует только FTS5 и пересобирает индекс при каждом поиске; Kuni — только перебор косинусом по эмбеддингам в файлах. Спецификация требует гибрид с обязательным NumPy-fallback.

## Решение
FTS5 (external content) поддерживается триггерами/транзакциями; эмбеддинги float32 в BLOB с model_id; кандидаты отбираются по scope и сравниваются NumPy; списки сливаются RRF (k=60). sqlite-vec и FAISS — опциональные extras.

## Альтернативы
Внешняя векторная БД — лишний сервис. Только sqlite-vec — версия < 1.0, нельзя делать обязательной.

## Последствия
Нужен бенчмарк перебора на реалистичном объёме в Phase 2; при смене модели эмбеддингов — переиндексация по model_id.
