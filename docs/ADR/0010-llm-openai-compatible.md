# ADR-0010: LLM через OpenAI-compatible API, по умолчанию OpenRouter

- Статус: **принято** (2026-11-08, решение владельца)

## Контекст
Все модели — через API; владелец сам задаёт URL и модель. По документации OpenRouter (проверено 2026-11-08 на openrouter.ai/docs) есть эндпоинты /chat/completions, /embeddings, /audio/transcriptions (STT), /audio/speech (TTS, совместим с OpenAI Audio Speech API) и /images.

## Решение
- Один провайдерский интерфейс OpenAI-compatible, `base_url` + `api_key` + имя модели в конфиге.
- Отдельные «роли» моделей: `chat` (ответ), `utility` (план, классификатор адресата, консолидация; если не задана — та же, что chat), `embedding`, `vision`, `stt`, `tts`, `image`. Любую роль можно отключить.
- Перед стартом — проверка capabilities каждой роли запросом к API; недоступная роль отключается с записью в диагностике.
- Другие провайдеры из SPEC_V3 (Anthropic, Gemini, OpenAI) добавляются тем же интерфейсом или отдельными адаптерами позже.

## Последствия
- Конкретные модели и цены не фиксируются в коде.
- Что конкретные модели OpenRouter поддерживают tool calling, vision и аудио — проверяется при старте, а не предполагается.
