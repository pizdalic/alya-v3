# ADR-0002: TDLib userbot — основной транспорт, Bot API — резервный

- Статус: **принято** (2026-11-08, решение владельца)

## Контекст
Аля живёт на пользовательском аккаунте @AlysiaNya; владелец выбрал режим userbot. Сборка TDLib из исходников долгая и хрупкая.

## Решение
- Основной адаптер — TDLib через собственный тонкий клиент поверх tdjson (prebuilt libtdjson, без сборки). Уточнено в Phase 4: Pytdbot не используется — нам нужны десяток методов, а своя обёртка проще тестируется фейком и не тянет лишний API.
- Bot API адаптер на aiogram 3.x — резервный транспорт и тестовый стенд. Ядро обязано работать без TDLib (тесты, CI).
- Оба адаптера приводят события к одному внутреннему формату; ядро не знает, какой транспорт активен.
- Кому адресовано сообщение в группе, решает Addressee Detector (ADR-0007): явные сигналы плюс продолжение разговора без reply.

## Альтернативы
- Только Bot API — теряется существующий аккаунт и функции пользователя.
- python-telegram 2.0.0 вместо Pytdbot — запасной вариант.
- Сборка TDLib из исходников — долго и хрупко.

## Последствия
- Риск ограничения аккаунта (ToS) принят владельцем; меры в SECURITY.md (T13, T14).
- Bot API адаптер — **другой аккаунт** (бот), он не видит чаты @AlysiaNya и не заменяет её при блокировке; это тестовый стенд, а не настоящий резерв.
- Нужны api_id/api_hash, интерактивная первичная авторизация и защищённое хранение сессии.
- Лицензия Pytdbot и tdjson и поддержка нужной архитектуры CPU проверяются до Phase 4.
