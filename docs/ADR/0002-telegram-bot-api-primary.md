# ADR-0002: TDLib userbot — основной транспорт, Bot API — резервный

- Статус: **принято** (2026-11-08, решение владельца; пересмотр первоначального предложения)

## Контекст
Аля живёт на пользовательском аккаунте @AlysiaNya, как и в alya-v2. Спецификация предлагала Bot API основным, а TDLib опциональным, но владелец подтвердил режим userbot. Kuni собирает TDLib из исходников; спецификация запрещает такую сборку в Docker.

## Решение
- Основной адаптер — TDLib через Pytdbot + tdjson (prebuilt libtdjson, без сборки).
- Bot API адаптер на aiogram 3.x — резервный транспорт и тестовый стенд. Это сохраняет критерий приёмки «работает без TDLib».
- Оба адаптера приводят события к одному внутреннему формату; ядро не знает, какой транспорт активен.
- Правило «в группах только mention/reply» реализуется в коде, так как userbot видит все сообщения.

## Альтернативы
- Только Bot API — теряется существующий аккаунт и функции пользователя.
- python-telegram 2.0.0 вместо Pytdbot — запасной вариант.
- Сборка TDLib из исходников — запрещена спецификацией, долго и хрупко.

## Последствия
- Риск ограничения аккаунта (ToS) принят владельцем; меры в SECURITY.md (T13, T14).
- Нужны api_id/api_hash, интерактивная первичная авторизация и защищённое хранение сессии.
- Лицензия Pytdbot и tdjson и поддержка нужной архитектуры CPU проверяются до Phase 4.
